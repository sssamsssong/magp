## 2026-08-07~09 (젯슨 — 계측 신뢰성 · μ 실측 · 속도 프로파일 물리화)

### 계측 파이프라인 (slip_friction)
- **★ ICP 부호 반전 수정** — `_icp` 가 찾는 `src→dst` 변환은 **차체 운동의 역**인데 그대로 속도로 썼다. 전진 중 `v̂_x` 가 음수라 `|v_wheel−v̂_x|` 가 항상 ≈2v 가 되어 **슬립 판정·자동 임계값 교정이 통째로 무의미**했다 (합성 검증: 차 +0.20m 전진 → 옛 코드 −0.20)
- **조향 클램프 추가** — `/commands/servo/position` 은 클립 **전** 지령이다. 좌 락 20.7° 를 지령 31.5° 로 기록해 `ω_kin` 이 1.5배 부풀었고, 각슬립이 79~91% 행에 찍힌 주원인이었다. `servo_min/max`(vesc.yaml)로 클램프
- **레버암 보정** (`lidar_x: 0.27`, base_link→laser TF) — ICP 는 LiDAR 위치의 속도를 재는데 슬립각은 차체 기준이라 `ω·x` 가 횡속도로 샌다. |β| 중앙값 **13.2° → 2.4°**
- **★ 종방향 슬립 판정 기본 OFF** (`enable_lin_slip: false`) — 연속 스캔 정합으로는 `v̂_x` 를 **원리적으로 못 얻는다**. 잔차 지형을 재보면 dx 를 0→0.36m 훑어도 잔차가 20.2~21.2mm 로 평평(정보 없음). 같은 기하가 횡방향은 반대로 강하게 구속(±0.1m 에 20.6→107mm)하므로 `v̂_y`·`ω̂` 는 쓸 수 있다. 참고 논문(2509.15423)이 `v̂_x` 를 쓴 건 스캔 정합이 아니라 **지도 기반 EKF** 라서
- **ICP 개선** — 베이스라인을 `icp_hz` 로 실제 제어(옛 코드는 항상 스캔 간격 25ms), 다중 시작+잔차 선택으로 0 락인 회피, dst 솎기 제거(최근접점 양자화 오차가 재려는 횡변위보다 컸다), LiDAR 속도 LPF 를 IMU 와 분리
- **모션 디스큐 추가했으나 기본 OFF** — 물리적으로는 옳지만 실측 이득이 없었다(|β| 2.5→2.4°, 저요레이트 95%p 는 14.8→16.4° 로 악화). 두 스캔이 같은 방식으로 찌그러지면 ICP 의 **상대** 변환에서 공통 성분이 상쇄되기 때문
- **패널에 롤 무관 `μ_k` + 포화 판정** — 속도 구간별 상위 20개 중앙값으로 스파이크 내성(3.0g 주입해도 대표값 유지 확인). "평평해짐 → 여기가 한계" 를 주행 중에 본다
- **`slip_replay` 신규** — bag 오프라인 재생. `--voser-mu`(μ 두 방식 비교) / `--calib-lever`(레버암 역산) / `--radius`(휠·롤 무관 `μ=R·ω²/g`) / 충격·오버스티어 제외 / 휠 스핀 진단
- **`/scan` bag 자동 녹화** — ICP 튜닝은 CSV 로 못 한다(추정이 끝난 결과만 남음). 차를 굴리지 않고 노트북에서 재생하며 고칠 수 있게

### 캘리브레이션
- **★ 오도메트리 8.9% 보정** — `speed_to_erpm_gain: 4614 → 4203`. 줄자 6회 실측으로 표시 속도가 실제의 **91.1%**. IMU·LiDAR 를 전혀 안 쓰는 독립 검증. **같은 지령에 차가 약 9% 느려진다** — 그동안 계획보다 빨리 달리고 있었다. `odom_scale` 도구 신규
- **★ μ 1.0489 → 0.400 (실효 그립)** — 화강석 타일+먼지. 독립된 세 방법이 0.30~0.48 에 수렴(`v·ω` 99%p / 기하학 / 팀원 곡률실측). **아직 추정치 0.400±0.08**
- **★ `mu` 는 마찰계수가 아니다** — MAP 논문 III-B `"peak value D̃ is in fact μ·Fz,i·Di"`. 실효 그립 = **`mu × pac_D`**. 논문 수치로 검증(1.0489×1.2084=1.267g ↔ 본문 "1.25 g"). 실측 0.40g 재현하려면 `mu = 0.348`
- **컨트롤러와 LUT 생성기가 다른 타이어를 쓰고 있었다** — 컨트롤러 B=3.8/D=1.15 vs 생성기 B=3.629/D=1.2084. `[map]` 을 단일 소스로 통일, LUT 재생성(`docs/lut_grip040/`, 최대 0.398g)
- **IMU 축 매핑 검증** — 독립 기준(`dv/dt`, `v·ω`)으로 교차검증. `a_y=+imu.x`, `a_x=−imu.y` 확인. **종축(−0.993)은 정확한데 횡축(+1.110)만 11% 틀린다** → 6축 IMU 가 횡가속과 중력 기울기를 구분 못 하는 **원리적 한계**(롤). 필터로 못 고친다 — 노이즈가 아니라 편향(R²=0.9, 절편 0)

### 속도 계획 (전면 개편)
- **★ 상한 개념 제거, 세 컨트롤러 전부 물리로** (`speed_profile.py` 공용) — `clip(v,min,max)` 는 max 가 CSV 속도보다 낮으면 **전 구간이 잘려 등속 주행**이 된다. Stanley 가 q1_max=1 인데 CSV 0.75~6.0㎧ 라 **직선에서도 코너에서도 1㎧** 로 돌던 것의 정체
- **마찰원 결합 forward-backward** — 곡률 한계 → 역방향(제동) → 전진(가속), `a_lon = a_cap·√(1−(a_lat/a_g)²)`. 검증: 예산 초과 0/400점, 합성 가속이 마찰원에 정확히 접함, 최대 가속/감속이 각 한계와 일치
- **`grip_util`(η) 이 유일한 속도 노브** — 속도가 아니라 **마찰 예산**에 곱한다. 속도를 k 배 하면 요구 횡가속은 k² 배라 어느 코너가 한계인지까지 바뀐다. `v ∝ √η` 이고 직선은 종가속·구간길이가 지배해 균일하게 안 줄어든다
- **gap_follower 도 물리로** — 레이싱라인이 없지만 **자기 조향각이 곧 곡률**(κ=tan δ/L). "조향 크면 0.6배" 임의 계수를 `v ≤ √(a_g/κ)` 로 교체 — 노면·기하가 바뀌면 자동으로 따라간다
- **`q1_max`~`race_max` 삭제** — 모드별 위험도는 평평한 상한이 아니라 `limits.grip_util` 로. `speed.hard_cap`(0=끔)만 물리 무관 안전천장으로 남김
- **`speed_scale`·`a_brake`·`mu_cap` 폐기** — 값이 남아 있으면 경고하고 무시. `a_brake 6.09㎧²` 는 이 노면 총 그립(3.92)의 **1.55배**라 물리적으로 불가능한 감속선이었고, 전진 패스가 없어 코너 탈출 시 순간이동을 가정했다
