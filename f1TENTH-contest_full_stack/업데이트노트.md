※ 오늘 것은 **전부 미커밋**이다. 내일 확인 주행 뒤에 커밋한다.

### ★ 코너 안쪽 파고듦 — 8/11 의 과조향이 아니었다
- 8/15 주행 **29회**를 다시 재보니 **곡률비 중앙 1.005 로 정상**인데(도는 반경은 맞다) 위치만 안쪽으로 +0.088m(문제의 q3 는 +0.115m, 코너 표본의 83%) 치우쳐 있었다. 같은 반경의 원을 안쪽에서 그린다 — **다른 고장이다**
- 원인: 조향 법칙이 `atan(2·wb·sinη/L1) + α_f` 뿐 **횡오차 항이 없다.** 순수 L1 유도라 곡선에서 정상편차가 0 으로 안 간다. 편차 ∝ L1² 이고 L1 = l1_k·v 라 **속도의 제곱**으로 큰다 (2.8㎧ 0.088 → 4.5㎧ 0.228 → 5.2㎧ **0.304m**)
- 예측 L1²/8R = 0.184 vs 실측 0.115 — **29회에 걸쳐 비가 0.48 로 일정**했다(α_f 가 절반 상쇄). L1 과 치우침의 상관 +0.43
- 지금은 안 위험하다 — 맵 거리변환으로 잰 코너 벽 여유 최소 **0.400m**(8/15 의 `--apex-extra 0.40` 이 덮고 있다). **속도를 올리면 그 여유를 다 먹는다**

### ★ "mu 를 살짝 올리면?" — 정확히 반대다
- 조향 쪽 `α_f = pacejka_inv(F_yf/(mu·Fzf))` 는 mu 를 올리면 줄지만, **속도 프로파일이 같은 mu 를 쓴다**: `a_lat = v²κ = grip·μ·pac_d·g ∝ mu` 라 `F_yf/(mu·Fzf) = a_lat/(mu·g) = grip·pac_d = 1.150` — **mu 가 약분된다.** 마찰 한계에서 도는 코너면 **아무리 올려도 α_f 는 그대로**
- 속도 쪽은 상쇄가 없다. `v ∝ √mu` → L1 ↑ → 치우침 ↑ (0.42→0.50 이면 0.115→0.137m, 벽 여유 0.400→0.378)
- 게다가 0.42 는 8/11 에 **양쪽에서 좁혀 확정한 값**이고(0.45 는 코너 슬립), 코너 `a_lat` 의 p90 이 이미 **예산의 102%** 다
- **mu 는 "타이어가 얼마나 버티나" 이고 문제는 "조준점이 코너 반경만큼 멀다" 였다. 축이 다르다**

### ★ 코너에서만 L1 을 자른다 (`map.l1_curv_k: 1.0`)
- `L1 = min( max(l1_min, l1_k·v),  max(l1_min, l1_curv_k/|κ|) )`. κ 는 **현재 위치부터 L1 앞까지의 최대값** — 파고듦은 조준점이 먼저 코너에 들어가 일찍 돌기 시작하는 것이라 코너에 닿은 뒤 줄이면 늦다. `l1_curv_k` 는 곧 **L1/R**
- `l1_k` 를 그냥 내리면 안 된다 — 08/09 고속 직선 요 진동 대책으로 **올린** 값이다. 편차는 코너에서만 생기니 코너에서만 줄인다. 하한은 항상 `l1_min`(08/06 진동 방어선)
- 값은 실패 주행에 **재생**해서 골랐다: 끔 2.06m/0.115m → **1.0 은 1.32m/0.047m**(L1/v 0.75→0.55s, 지연 290ms 의 2.59→1.89배)
- `_find_lookahead` 와 `_steer_map` 이 L1 을 각자 계산하던 것도 고쳤다 — η 는 그 L1 로 찍은 점에서 나온 것이라 어긋나면 기하가 깨진다

### ★ 실차: 큰 코너는 고쳐지고 타이트한 코너가 밀렸다 → **시간** 하한 (`l1_curv_tmin: 0.50`)

- `l1_curv_k` 를 올려 풀면 코너 본체까지 풀려 큰 코너 성과가 되돌아간다(1.3 → 치우침 0.092→0.155). **속도가 붙은 진입만** 풀어야 한다 → 하한을 시간으로
- 0.50s 는 재생으로 **코너 본체 L1(1.32)을 안 건드리는 최대값**(0.55 부터 깎인다). 전방주시 시간의 최저값 **0.326s → 0.500s**(지연의 1.13→1.72배)

- **1v1 상대 예측을 레이싱라인 s 를 따라가게** — 유클리드 `p+v·t` 는 코너에서 틀린다

- **★ ICP 부호 반전 수정** — `_icp` 가 찾는 `src→dst` 변환은 **차체 운동의 역**인데 그대로 속도로 썼다. 전진 중 `v̂_x` 가 음수라 `|v_wheel−v̂_x|` 가 항상 ≈2v 가 되어 **슬립 판정·자동 임계값 교정이 통째로 무의미**했다 (합성 검증: 차 +0.20m 전진 → 옛 코드 −0.20)

### 속도 계획 (전면 개편)
- **★ 상한 개념 제거, 세 컨트롤러 전부 물리로** (`speed_profile.py` 공용) — `clip(v,min,max)` 는 max 가 CSV 속도보다 낮으면 **전 구간이 잘려 등속 주행**이 된다. Stanley 가 q1_max=1 인데 CSV 0.75~6.0㎧ 라 **직선에서도 코너에서도 1㎧** 로 돌던 것의 정체
- **마찰원 결합 forward-backward** — 곡률 한계 → 역방향(제동) → 전진(가속), `a_lon = a_cap·√(1−(a_lat/a_g)²)`. 검증: 예산 초과 0/400점, 합성 가속이 마찰원에 정확히 접함, 최대 가속/감속이 각 한계와 일치
- **`grip_util`(η) 이 유일한 속도 노브** — 속도가 아니라 **마찰 예산**에 곱한다. 속도를 k 배 하면 요구 횡가속은 k² 배라 어느 코너가 한계인지까지 바뀐다. `v ∝ √η` 이고 직선은 종가속·구간길이가 지배해 균일하게 안 줄어든다
- **gap_follower 도 물리로** — 레이싱라인이 없지만 **자기 조향각이 곧 곡률**(κ=tan δ/L). "조향 크면 0.6배" 임의 계수를 `v ≤ √(a_g/κ)` 로 교체 — 노면·기하가 바뀌면 자동으로 따라간다
- **`q1_max`~`race_max` 삭제** — 모드별 위험도는 평평한 상한이 아니라 `limits.grip_util` 로. `speed.hard_cap`(0=끔)만 물리 무관 안전천장으로 남김
- **`speed_scale`·`a_brake`·`mu_cap` 폐기** — 값이 남아 있으면 경고하고 무시. `a_brake 6.09㎧²` 는 이 노면 총 그립(3.92)의 **1.55배**라 물리적으로 불가능한 감속선이었고, 전진 패스가 없어 코너 탈출 시 순간이동을 가정했다
