# Stanley 조향 게인 튜닝 (2026-07-21)

## 대상 파라미터

`race_script.yaml` → `stanley_controller.py` 에서 쓰는 6개 게인.

```
steer_ff = ff_gain * atan(wheelbase * κ)                              # 피드포워드
steer    = steer_ff + gain * (yaw_err - atan2(k * cte, v + ks))       # 피드백
steer    = steer_lpf * steer + (1 - steer_lpf) * steer_prev            # 저역통과
```

(출처: `src/race_stack/race_stack/stanley_controller.py`)

<details>
<summary><b>파라미터별 의미</b></summary>

- **gain (stanley_gain)** — 피드백(요각오차 + 횡오차 보정) 전체에 곱하는 게인.
  ↑ 크면 경로 추종이 빡빡해지지만 너무 크면 좌우로 흔들림(오실레이션).
  ↓ 작으면 부드럽지만 코너에서 라인 이탈(cutting) 가능.

- **k (stanley_k)** — 횡방향 오차(CTE, 경로에서 옆으로 벗어난 거리)를 조향각으로 바꾸는 게인.
  ↑ 크면 라인 복귀가 빨라지지만 저속에서 과민/떨림.
  ↓ 작으면 복귀가 느려 코너 안쪽으로 파고들 수 있음.

- **ks (stanley_ks)** — 속도항 `(v + ks)` 의 소프트닝 상수.
  저속(출발/정지 근처)에서 CTE 게인이 과도해지는 것을 억제.
  ↑ 크면 저속에서 조향이 둔감·안정적. ↓ 작으면 저속에서 조향이 민감/떨림.

- **ff_gain** — 곡률 기반 피드포워드 게인. 오차가 생기기 전에 앞으로 올 코너
  곡률만 보고 미리 조향을 넣어줌.
  ↑ 크면 코너 진입을 더 일찍/과감하게 꺾음(반응성↑, 너무 크면 과도조향).
  ↓ 작으면 순수 피드백에 가까워져 코너 반응이 늦어짐.

- **ff_preview_sec** — 피드포워드가 몇 초 앞의 웨이포인트 곡률을 미리 보는지
  (서보 지연 보상). `preview 거리 = speed × ff_preview_sec`.
  ↑ 크면 더 먼 미래를 보고 미리 꺾음(고속에 유리, 너무 크면 실제 코너보다 일찍 꺾임).
  ↓ 작으면 지연 보상 부족으로 반응이 늦어짐.

- **steer_lpf** — 최종 조향각 저역통과 필터 계수. `1.0` 이면 필터 없음(즉시 반영).
  ↓ 낮추면 조향이 부드러워지지만 반응 지연 발생(너무 낮으면 코너를 못 따라감).

</details>

## 실주행 관찰 (2026-07-21) 및 튜닝 방향

RViz에서 웨이포인트(초록/빨강)와 실주행 궤적(파랑)을 비교한 결과:

- 파란 실주행 경로가 **코너 전 구간에서 일관되게 웨이포인트보다 바깥쪽으로 부풀어 있음**
  (네 모서리 전부 동일 패턴, 여러 랩이 거의 겹쳐서 반복됨 — 좌우로 흔들리는
  오실레이션은 없음)
- → 조향이 "떨려서" 생기는 문제가 아니라, 코너를 도는 힘 자체가 부족한
  **체계적인 언더스티어**로 판단

### 조절 우선순위

1. **`ff_gain` ↑ 먼저** (기존 0.8 → 1.1~1.3 정도로 소폭씩)
   코너 진입 시 미리 꺾는 각도를 키워 바깥으로 밀리는 것을 원천적으로 줄임.
   (현재 값 0.8 은 기준값 1.0 보다도 낮아 오히려 억제하고 있는 상태였음)
2. 그래도 밀림이 남으면 **`k` ↑** (1.0 → 1.2~1.3) — 벗어난 후 라인 복귀 속도를 높임
3. 1·2번 반영 후에도 부족하면 **`gain`** 소폭만 (1.5 → 1.6~1.7) —
   오실레이션이 관찰되기 시작하면 바로 되돌릴 것
4. **`ff_preview_sec`** (현재 1.0초) 은 밀리는 시점이 코너 시작 지점과 맞물려 보여
   지금은 우선순위 낮음. 1·2번 조정 후 "코너 진입 전부터 너무 일찍 꺾인다" 나
   "코너를 지나서도 계속 밀린다" 같은 타이밍 문제가 보이면 그때 조정
5. **`ks`, `steer_lpf`** 는 현재 패턴(부드러운 바깥쪽 편향, 떨림 없음)과 무관해
   보여 지금은 그대로 둠

한 번에 하나씩 바꿔가며 rviz로 확인할 것. 튜닝 기록은 Notion
"Stanley 조향 게인 값 실험실" 데이터베이스에 랩별로 남긴다.

## 최고속도(q2_max 등)를 올릴 때 게인은 어느 방향으로 바뀌어야 하나 (2026-07-23)

**전제**: 이 트랙 웨이포인트(`track_2nd_clean_wp.csv`)의 목표속도는 전 구간
2.523~4.0 m/s 이다 (`gen_waypoints.py`의 `v = clip(sqrt(A_LAT_MAX/κ), V_MIN=1.0,
V_MAX=4.0)`, 이 트랙 최급코너 기준 계산값 — `V_MIN` 바닥이 아니라 곡률로 결정된
값). 따라서 **`q2_max` 가 2.523 미만인 동안은 코너·직선 구분 없이 전 구간이
그 상한으로 균일하게 잘린다.** 2.523을 넘는 순간 처음으로 코너마다 실제로
다른 속도가 들어가기 시작하므로, 이 지점을 넘는 건 "한 스텝 더"가 아니라
별도의 체크포인트로 다뤄야 한다.

속도가 오를 때 6개 게인이 전부 같은 방향으로 움직이지 않는다 — 오히려
서로 반대로 당기는 것들이 있다.

| 게인 | 방향 | 이유 |
|---|---|---|
| **ff_gain** | → / 소폭 ↑ (한계 있음) | `atan(wheelbase·κ)`는 원래 속도 무관한 기구학값. 고속일수록 타이어 슬립 증가로 실질 언더스티어가 커져 소폭 보정 필요할 수 있으나, 그립 한계(0.9g 가정)를 넘으면 더 올려도 무의미 |
| **k** | ↑ (신중하게, 부분 보상만) | `atan2(k·cte, v+ks)`는 분모에 v가 있어 속도가 오르면 같은 k라도 복귀력이 저절로 약해짐 → 밀림 유지하려면 k를 키워야 함. 단 이 1/v 감쇠는 Stanley 설계상 **고속 안정성을 위해 일부러 넣은 것**이라, 완전히 상쇄할 만큼 올리면 고속 오실레이션이 돌아올 수 있음 |
| **gain (전체 피드백)** | ↓ / → (직관과 반대) | 서보 반응 지연은 속도와 무관하게 고정 → 속도가 오르면 같은 지연시간 동안 차가 더 이동해 위상지연(phase lag)이 커지고 오실레이션 문턱에 가까워짐. "고속이니 더 세게"가 아니라 "고속일수록 같은 게인도 더 위험해진다" |
| **ff_preview_sec** | ↓ | 미리보기 거리 = `speed × ff_preview_sec` → preview_sec을 안 건드려도 속도만 오르면 거리가 저절로 늘어남. 서보 지연 보상이 목적이므로 지연시간 자체가 고정인 이상 값도 고정이 맞고, 안정성 여유를 위해 오히려 살짝 낮추는 쪽이 안전 (0.38→0.7 실험에서 벽 충돌급 공진 확인됨) |
| **ks** | → (영향력 자체가 옅어짐) | `(v+ks)`에서 v가 커질수록 ks 비중이 상대적으로 작아짐. 원래 저속 과민 방지용이라 속도가 오를수록 존재감이 옅어지는 파라미터 |
| **steer_lpf** | ↑ (필터 약하게, 1.0에 가깝게) | 같은 필터 지연시간이라도 고속에서는 그동안 이동거리가 더 커짐 → 필터가 주는 실제 지연거리가 속도에 비례해 늘어남. 새로운 떨림이 없는 한 고속일수록 필터를 더 약하게 두는 게 유리 |

**요약**: `k`만 소폭 올리고 나머지, 특히 `gain`과 `ff_preview_sec`은 그대로
두거나 오히려 낮추는 쪽이 이론적으로 안전하다. 실제로 겪은 두 번의 실패
(`ff_preview_sec` 0.38→0.7 공진, `q2_max` 1.5→3.0 급점프 충돌) 모두 이
예측과 일치한다.

**실무 지침**
- 속도 증분은 작게(±0.3~0.5 m/s), 특히 2.523 부근은 더 신중히
- 매 속도 단계마다 RViz 코너 밀림/오실레이션 육안 확인 + `/drive`
  steering_angle 이 `max_steer(0.36)`에 포화되는지 확인을 반복
- 오실레이션 없이 매끈하게 계속 바깥으로 밀리기만 하고 조향이 포화돼
  있다면 게인 문제가 아니라 물리적 그립 한계 — 그 지점은 게인이 아니라
  웨이포인트 목표속도(`gen_waypoints.py`의 실측 마찰계수 재조정)를
  낮추는 쪽으로 접근할 것
- Notion 기록에는 그 시점의 `q2_max`(혹은 해당 모드 max speed)도 같이
  남길 것 — 게인의 좋고 나쁨이 이제 속도에 종속적이라 속도 없이는
  기록의 의미가 없음
