## 1. 차량 기하 · 질량

```
휠베이스 L        0.324 m   [실측]  ← 컨트롤러가 실제로 쓰는 값
질량 m            3.74 kg   [실측]
CoG 높이 h        0.074 m   [미검증]
관성 I            0.04712 kg·m²  [미검증]
```

### ⚠ lf / lr 이 두 곳에서 **서로 반대**다 — 노트북이 정해줄 것

```yaml
map:            lf: 0.1757   lr: 0.1441   # L=0.3198, 후축 하중분율 0.549 (뒤가 무겁다)
sim_vehicle:    lf: 0.15875  lr: 0.17145  # L=0.3300, 후축 하중분율 0.481 (앞이 무겁다)
```

`lf` 는 CoG→전륜 거리다. 두 설정이 **무게중심이 앞에 있는지 뒤에 있는지**를
정반대로 말하고 있다. 이게 중요한 이유:

* `a_lon_acc` 자동 유도가 `a_g · lf/L` 다 (후륜구동이라 후축 하중분율이 한계).
  0.549 vs 0.481 이면 가속 상한이 14% 달라진다.
* On-Track SysID 의 전/후륜 슬립각 분해가 lf/lr 로 결정된다. 부호가 뒤집히면
  전륜 커브를 후륜 데이터로 맞추게 된다.

팀에서 **앞뒤 하중분포를 실측했다**고 했으니 그 값으로 양쪽을 통일할 것.
통일 후 `map.lf/lr`, `sim_vehicle.lf/lr`, `race.launch.py` 폴백,
`sysid_nn`, `vehicle_sim` 을 전부 맞춰야 한다.

### 조향 (2026-08-09 변경)

```
servo = 0.3954 − 0.761·δ          [실측] 08/07 steer_trim.py 4회 자동측정
servo_min 0.12 / servo_max 0.85   ← 08/09 좌측을 0.15 에서 넓혔다
기구 스토퍼 실측: 좌 servo 0.100 / 우 0.860   [실측] 08/05

  → 좌 한계 δ = +0.3619 rad = 20.73°   (R_min 0.856 m)
     우 한계 δ = −0.5974 rad = 34.16°   (R_min 0.475 m)
```

**★ 조향이 좌우 비대칭이다.** 시뮬은 `s_max: 0.36` 하나로 대칭 가정하고 있다.
현재 트랙(halfhot)은 전 구간 좌회전이라 실질 한계는 **좌측 20.73°** 이고,
`max_steer: 0.36` (20.63°) 이 그것과 거의 같아 지금은 우연히 맞는다.

우회전이 섞인 트랙을 최적화할 때는 이 비대칭을 넣어야 한다. 링키지를 재중심하면
좌우 ±27.4° 대칭이 되지만(가동범위 0.100~0.860 의 중점 0.480 vs 현재 중립 0.3954),
그건 기구 작업이라 아직 안 했다.

## 2. 마찰 — μ

```
μ_eff = mu × pac_D = 0.348 × 1.15 = 0.400        [추정] ± 0.08
```

**★ `mu` 단독이 0.40 이 아니다.** MAP 논문 III-B 대로 Pacejka 피크가 `μ·Fz·D` 라
실효 그립은 `mu × pac_D` 다. 그래서 yaml 의 `map.mu` 는 0.348 이다.
`sim_vehicle.mu` 는 0.40 인데 이쪽은 Pacejka D 를 따로 안 곱하는 모델이라 맞다.
**두 값이 다른 건 버그가 아니다.**

### 0.400 의 근거 (08/08, 서로 독립인 세 방법)

| 방법 | 결과 |
|---|---|
| ① μ_k = v·ω/g 의 99%p 0.487 → 휠 스핀 보정(÷1.21) | 0.40 |
| ② 기하 — 조향 20.7°(기구학 R 0.85m)로 돌았는데 실제 R ≈ 3.0m | 0.30~0.36 g |
| ③ 팀원 곡률 실측 A_LAT_MAX 3.7㎧² → 오도메트리 보정 후 | 0.45 g |

**이건 측정이 아니라 추정이다.** 한계점을 깨끗이 짚은 순간이 없었고(내내 넘겨서
돌았다), 데이터의 32%가 충격 오염(최대 17.2g)이었으며, 휠 스핀까지 겹쳤다.

### 08/09 주행이 μ 에 대해 말해주는 것

| 항목 | 값 | 함의 |
|---|---|---|
| 제동 최대 [실측] | −2.83 ~ −3.37 ㎧² | η=0.8 예산 3.14 와 거의 같다 → μ_eff ≥ 0.40 은 **맞다** |
| 가속 p95 [실측] | +1.72 ~ +2.42 ㎧² | 자동 유도 a_acc 1.72 와 부합 |
| 가속 최대 [실측] | +4.01 ㎧² (1회) | 이게 참이면 μ 가 0.67 이어야 한다. 휠 스핀 의심 — 신뢰 안 함 |

**η=0.8 에서 스무스하게 완주**했으므로 0.40 은 최소한 보수적이지 않다.
정반경(constant-radius) 주행으로 재확정하는 게 여전히 숙제다 —
반경을 고정하면 `μ = R·ω²/g` 로 자이로만 써서 휠 스핀·롤을 둘 다 피할 수 있다.

**★ 대회 노면은 우레탄이다. 지금 값은 연습장(화강석 타일 + 먼지) 기준이다.**

### Pacejka

```
pac_b 3.8   pac_c 1.3   pac_d 1.15   pac_e −0.5     [미검증]
C_Sf 2.1    C_Sr 5.4562                              [미검증]
```

전부 초기값이다. HyperMAP 의 On-Track SysID 가 채워야 할 자리인데,
`ontrack_sysid.py` 는 아직 합성 검증을 통과하지 못했다 (전륜 곡선 오차 ~16%,
후륜 39~79%). 원인은 가상 정상상태 램프에서 α_r 이 2.15° 까지밖에 안 올라가는 것으로
의심된다 — 후륜 곡선의 선형 구간만 보고 피크를 외삽하는 셈.

## 6. 노트북이 알아야 할 함정 세 개

### (a) 레이싱라인이 차보다 tight 했다 — 08/09 에 고침

```
라인 최소반경 (5점 평활)  0.91 m  → 필요 조향 19.5°
차량 최소회전반경 (수정 전) 0.97 m  → 좌 한계 18.48°
```

**속도와 무관하게 헤어핀을 기하학적으로 못 돌았다.** s=16m 에서 라인 바깥으로
0.39m 밀린 게 그립 부족이 아니라 이것이다. `servo_min` 을 0.15→0.12 로 넓혀
R_min 0.856m 로 만들어 해결했다.

**★ 앞으로 라인을 재생성할 때 `R_min ≥ 0.90 m` 제약을 넣을 것.**
지금 0.856 은 여유가 5% 밖에 없다. 안전하게는 1.0 m 를 권한다.

### (b) `steer` 열은 지령이지 실각이 아니다

수정 전에는 지령의 **25.8%** 가 서보 소프트 리밋에 잘려나갔다. 조향 포화
112 회가 **전부 좌회전**이었고 우조향은 한계 근처에도 안 갔다.
08/09 이전 로그로 조향 모델을 맞추면 잘린 구간이 그대로 들어간다 —
`δ_실각 = min(δ_지령, 0.3225)` 로 clip 한 뒤 쓸 것 (좌회전에 한해).

### (c) `grip_util` 이 `./race.sh q2` 에서 안 먹었다 — 08/09 에 고침

`race.launch.py` 가 `mode:=` 오버라이드 **전에** `grip_util` 을 풀어서,
yaml 의 `mode:` 값이 이겼다. q2 주행이 q1 과 똑같은 η=0.8 로 돌았고
(로그의 `cmd_v` 중앙이 3.02 로 q1 의 3.03 과 동일), 4.9㎧ 로 장애물에 돌진해
회피가 "전혀 안 되는" 것처럼 보였다.

같이 있던 두 번째 원인: 회피 호라이즌이 `l1_min=0.90` 시절 값(1.8m)이라
지금(1.4431)에 한참 모자랐다. 4㎧ 에서 필요한 거리는

```
L1 상승거리 1.8·L1/√2 = 2.90 m   +   기준선 램프 0.6m ÷ 0.9㎧ = 2.7 m   ≈ 5.6 m
호라이즌 = 3.0 m (obs_horizon_max 에 걸림)
```

`obs_horizon_min/sec/max` = 2.9/0.7/5.0, `shift_rate` 0.9→2.0 으로 고쳤다.
**아직 실차 검증 안 됨** — 젯슨이 다음 주행에서 확인한다.

`docs/grip_util_shadowing.md` 에 같은 종류의 함정(읽는 곳 ≠ 쓰는 곳)을 정리해뒀다.
`map_optimize.py` 는 이제 현재 mode 키에 쓴다.
