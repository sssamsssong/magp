# ★ gen_raceline 의 R_min 제약이 최종 경로에서 안 지켜진다

**발견 2026-08-09 (젯슨). 커밋 `2822718` 의 `--rmin` 제약 검증 중.**
젯슨은 코드를 안 고쳤다 — 고치는 방법이 셋인데 어느 쪽인지 노트북이 정하는 게 맞아서.

## 증상

`--rmin 0.9` (기본값)로 만든 `halfhot_clean_map_wp` 의 **실제 최소반경이 0.797m** 다.

```
QP 제약 상한        1/0.9 = 1.1111  1/m
최종 CSV 실제 κ_max        1.2553  1/m   → R 0.797 m   ← 13% 초과
```

QP 는 `[4] 최소 곡률 QP` 단계에서 `kappa_new = kappa_ref + E@alpha` 를 출력하는데,
**그 값은 제약을 만족한다.** 그래서 로그만 보면 성공한 것처럼 보인다.

이건 `docs/grip_util_shadowing.md` 와 같은 종류의 함정이다 —
**고쳤는데 아무 효과가 없으면서 고친 것처럼 보인다.**

## 왜 실차에서 문제인가

이 차는 좌우 조향이 비대칭이고, 현재 트랙(halfhot)은 **전 구간 좌회전**이다.

```
좌 조향 한계 (servo_min 0.12, 2026-08-09)   δ = 0.3619 rad = 20.73°
   → 최소회전반경  R = L/tan(δ) = 0.324/tan(0.3619) = 0.856 m
   → 곡률 한계     κ = 1.168 1/m
```

새 라인은 s = 15.8~15.9m (헤어핀)에서 이걸 넘는다.

| 라인 | 평활 κ_max | R | 좌한계 초과점 |
|---|---|---|---|
| `halfhot_clean_map_wp` (신규, `--rmin 0.9`) | 1.20 | **0.835 m** | 평활 2/279 · raw 6/279 |
| `halfhot_forza_opt_wp` (기존) | 1.09 | 0.914 m | **0** |

**제약을 넣었는데 이전 라인보다 나빠졌다.** 08/09 실차에서 정확히 이 지점(s=16m)에서
라인 바깥으로 0.39m 밀렸고, 조향 한계를 넓혀 고친 게 그 문제였다.

## 원인 — 셋이 겹쳐 있다

### ① ★ QP 격자(0.5m)와 출력 격자(0.1m)가 다르다 — 이게 지배적

```python
reftrack_u = interp_track(reftrack, stepsize=0.5)   # [2] QP 는 0.5m 격자
alpha = opt_min_curv(reftrack_u, ..., r_min=args.rmin)
raceline, el, kappa = build_raceline(..., stepsize=args.step)   # [5] 출력은 0.1m
```

곡률은 **2계 도함수**다. 0.5m 격자는 0.1m 격자에 나타나는 곡률 피크를 표현할 수 없다.
**같은 곡선을 격자만 바꿔 재보면** 이렇게 나온다:

```
최종 CSV 곡률을 격자별로 재계산 (곡선은 동일, 표본만 다름):
  0.1m (CSV 그대로)   |κ|_max 1.2553  → R 0.797 m   ← 실제로 주행하는 것
  0.2m                |κ|_max 1.2354  → R 0.809 m
  0.5m  ← QP 격자      |κ|_max 1.1004  → R 0.909 m   ← 제약(1.1111) 만족!
```

**0.5m 격자에서는 제약을 지키고 있다.** QP 는 거짓말을 안 했다 — 자기가 보는
해상도에서는 정말 만족한다. 다만 그 해상도가 차가 달리는 해상도가 아니다.

### ② 선형화 오차

```python
# 제약 2: |κ_ref + E·α| ≤ 1/r_min
```

`E·α` 는 **기준선 주위 1차 전개**다. 헤어핀은 α 가 가장 큰 곳이라 고차항이 가장 크다.
TUMFTM 원본이 해를 새 기준선으로 삼아 **재선형화 반복**을 도는 이유가 이것이다.

### ③ `build_raceline` 의 곡선이 QP 가 모델링한 곡선과 다르다

QP 는 `calc_splines` 의 조각별 3차 스플라인을 가정하는데, `build_raceline` 은
`splprep`(주기 + 가벼운 스무딩)으로 다시 만든다. 스무딩 파라미터가 곡률을 바꾼다.

①만으로도 `1.100 → 1.255` (14%)가 설명되므로 ②③은 부차적으로 보인다.
다만 ①을 고친 뒤에도 남는지 확인해야 한다.

## 고치는 방법 (셋 중 하나 — 노트북이 정할 것)

### A. 출력 격자에서 제약을 검증하고 반복 — 권장

QP 를 푼 뒤 `build_raceline` 까지 돌려 **최종 0.1m 곡률**을 재고, 넘으면
`r_min` 을 조여 다시 푼다. 2~3회면 수렴한다.

```python
target = args.rmin
r_eff  = target
for _ in range(5):
    alpha = opt_min_curv(reftrack_u, normvec, M_spl, w_veh=args.wveh, r_min=r_eff)
    raceline, el, kappa = build_raceline(reftrack_u, normvec, alpha, stepsize=args.step)
    r_act = 1.0 / np.abs(kappa).max()
    if r_act >= target * 0.995:
        break
    r_eff *= r_act / target          # 부족한 만큼 제약을 더 조인다
```

* 격자 불일치(①)와 선형화(②)와 스무딩(③)을 **전부** 흡수한다. 원인을 안 따져도 된다
* `--rmin` 이 **최종 경로 기준**이라는 뜻이 되어 사용자가 헷갈릴 여지가 없다
* 비용은 QP 2~3회. 지금 한 번에 몇 초라 문제 없다

### B. QP 격자를 출력 격자에 맞춘다

`interp_track(stepsize=0.5)` 를 `args.step`(0.1)으로. 원인 ①을 정면으로 없앤다.

* 노드 수가 56 → 279 로 5배. QP 는 N×N 조밀행렬(`H = E.T@E`)이라 **메모리·시간이 25배**다.
  279 정도면 아직 괜찮지만 큰 트랙에서는 부담이다
* ②③ 은 그대로 남는다. A 보다 원리적이지만 완전하지 않다

### C. `--rmin` 에 여유를 주고 재생성 (임시)

`--rmin 1.05` 정도. 지금 오차비가 `1.2553/1.1111 = 1.13` 이므로
`0.9 × 1.13 ≈ 1.02` 이상이면 목표 0.9 가 나온다.

* 코드 수정 없이 지금 당장 된다
* **트랙·맵이 바뀌면 계수가 달라진다.** 근본 해결이 아니고, 나중에 왜 1.05 인지
  아무도 기억 못 하는 상수가 된다. A 를 하기 전 임시방편으로만

### ★ 어느 쪽이든 반드시 같이 넣을 것 — 최종 검사

```python
r_act = 1.0 / np.abs(kappa).max()
print(f'  최종 R_min = {r_act:.3f} m  (목표 {args.rmin})')
if r_act < args.rmin * 0.995:
    print(f'  ⚠ R_min 제약 위반 — 차량 조향 한계 확인 필요')
```

지금은 `[4]` 에서 선형화 곡률만 출력하고 최종 곡률은 아무도 안 본다.
이 두 줄이 있었으면 애초에 안 나갔을 문제다.

## 목표값을 얼마로 둘까

```
차량 좌 최소회전반경 (현재)   0.856 m
```

* `--rmin 0.9` — 여유 5%. **너무 빠듯하다.** AMCL 오차·조향 지연·타이어 슬립이
  전부 이 안에 들어가야 한다
* `--rmin 1.0` 권장 — 여유 17%. 랩타임 손해는 이 트랙에서 미미할 것으로 보인다
  (기존 라인 0.914m 로 이미 η=0.8 완주했다)

**★ 이 값은 `servo_min` 에 걸려 있다.** 조향 한계가 바뀌면 같이 바뀐다.
`config/vesc.yaml` 의 `servo_min`/`offset` 을 건드리면 라인도 재생성해야 한다.

```
R_min(차량) = wheelbase / tan( (servo_min − offset) / (−gain) )
            = 0.324 / tan( (0.12 − 0.3954) / (−0.761) )
            = 0.856 m
```

## 참고 — 랩타임 영향은 거의 없다

μ_eff 0.400 기준 프로파일:

| 라인 | η | v 범위 | 중앙 | 예상 랩 |
|---|---|---|---|---|
| `halfhot_clean_map_wp` (신규) | 0.7025 | 1.48~4.85 | 3.06 | **10.1 s** |
| `halfhot_forza_opt_wp` (기존) | 0.80 | 1.57~5.00 | 3.08 | **9.9 s** |

**0.2초 차이다.** R_min 을 1.0 으로 올려 조금 더 잃더라도 "못 도는 구간이 없다"가
훨씬 가치 있다 — 08/09 실차에서 그 구간이 전체 CTE 의 최대치를 만들었다.
